# 升级与迁移

升级本身不复杂，出问题几乎都出在两件事上：**没备份**，以及**换了源包却没替换本地 jar 地址**。

## 升级前先做三件事

1. **记下当前版本**：设置页底部，或 [Releases](https://github.com/upchr/meow/releases) 里的 tag
2. **备份数据目录**：见 [备份与恢复](/guide/backup)
3. **确认源包还在手边**：升级不删配置，但从「内置源」形态迁移时必须重新导入

::: warning 跨大版本前一定先备份
1.0.x → 1.1.x 涉及运行时模块、配置字段的增减。出问题时能回退到旧数据和旧版本，
比事后排查快得多。
:::

## 各端升级

设置 →「更新」里的**更新中心**统一管壳、Node / Python 运行时与 fnOS 应用：显示当前版本、逐项「检查」。自动检查分两种：壳与 fnOS 应用在启动约 5 秒后静默检查、发现新版会弹框（同一个版本 24 小时内最多提示一次；点「稍后」后只有更高版本才再提示）；模块 / 插件最多 24 小时一次，只更新状态、不弹框。TV / PC 连到 fnOS 后端时，更新中心会多一行只读的「后端 fnOS 应用」，提示 NAS 上有新版——升级仍要在 NAS 上操作。

想回看每个版本改了什么：设置 →「关于」→ 版本历史，应用内直接拉 `history.json`，不用跳 GitHub。

![设置 →「更新」：更新中心逐项检查；更新源留空 = 内置默认源，备用源可选](/screenshots/update-center.png)

### Web / Docker

```bash
cd deploy/docker        # 不 clone 的部署：进编排文件所在目录
docker compose pull
docker compose up -d
```

- **默认跟随 `latest`**：`pull && up -d` 就是升级。只有在 `.env` 里钉了具体版本时，才需要先把 `MEOW_VERSION` 改成新 tag 再 pull（否则拉到的是旧版本）
- `data/` 是挂载目录，升级不覆盖
- 升级后 `docker compose ps` 四个容器都应是 `Up`，接口 503 说明 apiserver 没起来

### PC

- **应用本体**：设置 →「更新」→ 检查并安装
- **插件**：插件列表里远端版本更高时显示「可升级」，逐个点
- 应用与插件版本独立演进，**不要因为版本号不一致就以为装坏了**

::: tip 静默安装前先退出应用
如果手动跑 NSIS 安装包，先 `Stop-Process` 掉正在运行的猫窝，
否则文件占用会导致安装失败或装完还是旧版。
:::

### TV

1. 下载新 `meow-TV-<版本>.apk`
2. 覆盖安装（必须同签名，release 签名不变）
3. Node / Python 运行时在设置 →「运行时模块」里单独更新

```bash
adb install -r meow-TV-<版本>.apk
```

覆盖安装**保留**应用数据；`adb uninstall` 会清空，需要重新导入配置。

### 飞牛 fnOS

三条路，效果一样：

- 打开应用时**弹框**提示「发现新版本」（与 PC / TV 同一种弹框，可点「稍后」跳过该版本）
- 应用中心 → 猫窝 → 升级
- 应用内 设置 →「更新」

应用内更新会自动重启服务，弹框会等到服务恢复后自动刷新页面；数据目录不动。

::: warning fnOS 降级要先卸载
要走降级就「卸载 → 装旧 fpk」。卸载向导**默认「保留数据」**，不会清空应用数据，
只有显式选「删除数据」才会清（稳妥起见先备份）。
:::

## 从「内置源」的旧安装迁移

这一节只影响从「自带源包的全量版」换到公开壳的用户；新装用户可以跳过。类名看不懂没关系，照着步骤做即可。

如果你之前用的是自带站点配置与爬虫包的完整版，换成公开壳（或换新源包）时，
这一步最容易踩：

### 症状

导入成功、站点列表也有，但每个站点都报 `ClassNotFoundException` / `NoClassDefFoundError`，
或者干脆全是红的。

### 原因

导入时只换了站点表，**本地还留着旧配置里的 `spider` 字段**——指向一个已经不存在的 jar。
客户端按旧地址加载，自然找不到类。

### 正确做法

导入配置时勾选：

```
配置源 → 导入 → ☑ 用这份配置的顶层 spider 覆盖本地
```

界面上的原话是「用这份配置的顶层 spider 覆盖本地」，旁边的提示写着
「从全量版迁移/装源包时勾选；平时不要勾，会冲掉你手改的 jar 地址」。

### 迁移后核对四步

1. **站点数**与「N 个扩展」的数量是否和源包声称的一致
2. 搜索一个常见片名，能出结果
3. 点进详情，有线路与集数
4. 播一集，能出画面、进度条在走

哪一步断了，见 [常见问题](/guide/faq) 与 [诊断手册](/reference/diagnostics)。

### 源包现在是 dex 主入口

迁移到新源包时，统一用 `config.all.json` + **dex** jar：Fongmi/TV 直接加载，
猫窝 JVM 用导入期 `Dex2Jvm` 自动转 class。`spiderJvm` 只是可选的 JVM 优化，
不再是必需产物。细节见 [导入源包](/guide/source-pack#一份配置通吃三端)。

## 跨版本变化速查

| 变化 | 起始版本 | 影响 |
|---|---|---|
| TV 运行时模块（Node / 弹幕） | 1.1.0 | 模块 `min_sdk` 26；旧壳不认模块条目 |
| 飞牛版内置弹幕插件 | 1.1.0 | 复用应用中心 Node 22 |
| fnOS 应用内更新 | 1.1.3 | 旧版只能走应用中心 |
| 配置支持 `spiderJvm` | 1.1.6 | 旧版不认该字段，仍需 `config.jvm.json` |
| JVM 导入期 dex→class（dex2jvm） | 1.1.7 | 源包只需 dex；旧 JVM 仍要 `config.jvm.json` 的 class jar |
| TV Python 运行时（.py 源） | 1.3.0 | Chaquopy 模块 APK ×3 ABI；旧壳更新中心没有该行 |
| 运行时分层 `pyRuntimeAddr` | 1.3.0 | `.py` 优先 `pyRuntimeAddr`，未配回落 `jsRuntime`；老 pyrt 单地址部署不用动 |
| iOS 端内 VLCKit 播放 / 后端地址可配 | 1.3.0 | MKV/HEVC 端内直解；「后端地址」可指向局域网后端 |

更早的能力（端内网关、扫码推送）没有逐版本记录，判断依据以实际界面为准。
完整对照见 [版本兼容矩阵](/reference/compatibility)。

## 降级

| 端 | 做法 | 注意 |
|---|---|---|
| Docker | `.env` 钉回旧版本 tag 后 `pull && up -d` | 镜像 tag 必须存在 |
| PC | 卸载后装旧安装包 | 卸载默认保留 `%APPDATA%\com.meow.player` |
| TV | `adb install -d <旧 apk>` | `-d` 允许降级；签名必须一致 |
| fnOS | 先卸载再装旧 fpk | 卸载向导选「保留数据」，选删除才会清空 |

降级到不认 dex2jvm 的旧 JVM 时，`config.all.json` 里的 dex 不会被转换：
改用 `config.jvm.json`（顶层 `spider` 指向 class jar），或把 `spider` 指回 class jar。
`spiderJvm` 这类未知字段会被旧版忽略。

## 卸载与彻底清理

卸载本身不会删数据，**要清干净得自己删目录**。要留一份就先看 [备份与恢复](/guide/backup)。

| 端 | 怎么卸载 | 数据在哪 / 怎么清 |
|---|---|---|
| Web / Docker | `docker compose down`（**不要加 `-v`**，本项目用 bind mount，`down` 本来就不动数据） | 数据在编排文件旁的 `./data`（仓库版在仓库根 `data/`）；删掉这个目录才算清干净。镜像另用 `docker rmi` 删 |
| PC | Windows「设置 → 应用 → 已安装的应用」卸载，或重跑安装包选卸载 | `%APPDATA%\com.meow.player` 默认**保留**（含 `data/` 与 `plugins/`）；要彻底清就手动删这个目录 |
| TV | 系统里卸载应用 | 应用私有目录随卸载清空（壳声明了 `allowBackup=false`，卸载即丢）；重装要重新导入源包 |
| 飞牛 fnOS | 应用中心 → 猫窝 → 卸载 | 卸载向导**默认保留数据**；要彻底清得显式选「删除数据」 |

只清某一部分时：`data/config.sites.json` 是站点配置、`data/policy.json` 是运行时策略、
`data/poster*` 与 `data/cache` 可重建；收藏与观看进度的权威在各端 localStorage，
清后端数据不会删掉浏览器或客户端里的那份。

## 升级后自检

```
1. 后端健康：Web 看 /api/health，PC 看插件状态「运行中」
2. 站点数：与升级前一致（迁移除外）
3. 搜索 → 详情 → 播放 三段都通
4. 收藏与进度还在（确认数据目录没换）
```

第 4 步失败通常意味着数据目录被改了（容器挂载、便携版换了位置），见 [备份与恢复](/guide/backup)。

## 常见失败

| 症状 | 原因 | 处理 |
|---|---|---|
| 升级后站点全红 | 旧 `spider` 地址残留 | 重新导入并勾选覆盖 spider |
| 插件列表显示「需要更高版本的应用」 | 插件 `min_app_version` 高于当前应用 | 先升应用，或装旧插件 |
| 运行时模块装不上 | 壳版本低于 1.1.0，或 `min_sdk` 26 不满足 | 升壳 / 换支持 Android 8.0 的设备 |
| 升级后端口变了 | 插件端口协商顺延 | 设置页看实际端口，别写死 |
| fnOS 升级后版本没变 | 应用中心与内置更新源短暂不同步 | 隔几分钟重试，或回应用中心升 |
| 覆盖安装后配置没了 | 装成了「卸载再装」而不是覆盖 | 从备份恢复 |
